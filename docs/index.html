이 플랫폼은 어떻게 도는가 — How bit-habit runs

한 대의 Oracle Cloud ARM 서버 위 k3s(경량 쿠버네티스)가 *.bit-habit.com의 16개+ 서비스를 굴립니다. 이 페이지는 그 구조를 nginx 비유로 설명해요. 실시간 상태는 아래 headlamp에서.
A single OCI Ampere A1 box running k3s + Traefik + cert-manager serves every *.bit-habit.com service. This page explains the shape; headlamp shows it live.

2 · 요청이 들어오는 길 — the edge

별도 로드밸런서 없이 Traefik 파드가 호스트의 80/443을 직접 물고 있어요.

flowchart LR U["Browser"] -->|"DNS: *.bit-habit.com (wildcard)"| IP["OCI public IP\n158.180.71.122"] IP -->|":80"| R["Traefik :80\n308 redirect to https"] R --> T IP -->|":443"| T["Traefik :443\nTLS termination (wildcard cert)"] T -->|"match by Host header"| ING["Ingress rules\n(per subdomain)"] ING --> SVC["Service (ClusterIP)"] SVC --> POD["Pod (app container)"]

와일드카드 DNS라 새 서브도메인은 DNS 작업 없이 Ingress 규칙 한 줄이면 끝. A new subdomain = one Ingress rule, no DNS change.

3 · 와일드카드 TLS — 인증서 하나로 전부

*.bit-habit.com 와일드카드 인증서 하나를 cert-manager가 자동 발급·갱신하고 모든 서브도메인이 공유합니다.

sequenceDiagram participant CM as cert-manager participant DNS as Route53 DNS participant LE as Let's Encrypt participant T as Traefik CM->>DNS: write _acme-challenge TXT (DNS-01) LE->>DNS: verify TXT LE-->>CM: wildcard cert (*.bit-habit.com) CM->>CM: store in Secret "tls-secret" T->>CM: serve cert by SNI Note over CM,T: auto-renew before the 90-day expiry

4 · 배포의 현실 — push 하면 어떻게 live가 되나

⚠️ 정직 고지: 인프라 README는 "ArgoCD 자동동기"라 적혀 있지만 실제로는 ArgoCD 미설치 → 수동 kubectl apply가 현재 배포 방식입니다. (정적 사이트 일부는 GitHub Actions가 서버에 ssh로 git pull.)
Honesty note: the README claims ArgoCD auto-sync, but ArgoCD is not installed — deploys are manual kubectl apply today.
세 가지 "push → live" 방식
  • cron pull — 폴링. 단순하나 빌드·피드백 없음. 표준 아님.
  • GitHub Actions (push CI/CD) — 이벤트 기반. 정적 → Pages, 서버 → ssh pull.
  • ArgoCD (pull GitOps) — 클러스터가 git 감시·자동동기. k8s 표준, 여기선 아직 미설치.
